# FPGA 小规模数字系统开发技能包

> 来源：本队 2026 年竞赛项目「基于 Zynq-7000 的双通道 DDS 信号发生器」
> （EBAZ4205 / XC7Z010 + TLV5618A + 板载四按键 + 串口 + 网页上位机）。
> 这里收录的不是项目说明书，而是**开发过程中真正卡住我们的东西，以及下一次可以直接复用的部分**。

## 这个包解决什么问题

小规模 FPGA 项目的难点很少在算法上，而集中在四件事：

1. **软硬件怎么分**——哪些放 PL、哪些放 PS、哪些根本不该用 FPGA 做；
2. **综合报告怎么看**——WNS 负了到底是哪条路径，资源超了该砍谁；
3. **引脚与电平到底对不对**——社区资料经常是错的，照抄会浪费一整天；
4. **同一批坑反复踩**——编码、换行、路径中文、串口独占、时序不收敛。

对应地，本包分为四项内容：

| 目录 | 内容 | 与本题目是否绑定 |
|---|---|---|
| `01_prompts/` | 提示词工作流：让大模型做架构推导、综合报告解读、引脚核对 | **不绑定**，换题目换板卡仍可用 |
| `02_templates/` | 案例模板：工程骨架、一键构建脚本、按键约束模板、报告章节骨架 | 骨架不绑定；约束模板与具体器件绑定 |
| `03_checks/` | 校验脚本：解析实现报告并与基线比对、检查工程可复现性 | **不绑定**，只依赖 Vivado 报告格式 |
| `04_pitfalls/` | 踩坑清单：12 条错误的触发条件、现象、定位步骤、修复 | **不绑定**，绝大多数是通用问题 |

每项目录下都有自己的 README，写明适用场景、使用方法、已验证效果、失效条件。
**下面先给总的失效条件，这是使用前必须看的一段。**

---

## 失效条件（什么时候本包不适用）

诚实地说清楚边界，比夸大适用范围有用：

1. **`02_templates/pins_key4.xdc` 只对 EBAZ4205 + EXBOARD 扩展板成立。**
   换任何一块板卡，引脚编号全部作废，但其中的“上拉类型选择思路”和“按键低有效的判据”仍然成立。
   **不要**把引脚号抄到别的板子上。

2. **`02_templates/build.tcl` 假定单时钟域、无 IP 核、纯 RTL 工程。**
   一旦工程里用了 Block Design、MIG、AXI 互联或任何 IP，`create_project` + `add_files` 的流程不够用，
   需要改成 `add_files -fileset sources_1 ./xxx.bd` 并设置 `generate_target`。

3. **`03_checks/` 依赖 Vivado 2017.4 的报告文本格式。**
   2019 之后的版本报告表头与列顺序有变化，正则可能需要微调。脚本里已把正则集中在一处，便于改。

4. **`01_prompts/` 的第 2 条（综合报告解读）需要模型能读长文本。**
   把 300 行的时序报告贴进去，上下文短的模型会截断，结论会失真。推荐只贴“关键路径前 10 条 + 汇总表”。

5. **`04_pitfalls/` 的第 1、2 条只对“按键上拉到 VCC、按下接地”这类电路成立。**
   如果按键是“下拉到 GND、按下接 VCC”的接法，极性结论正好相反。**判据本身通用，结论不通用。**

## 怎么迁移到自己的题目（三步）

**第一步：先把 `04_pitfalls/` 从头读一遍（约 15 分钟）。**
它的价值是“提前知道哪些地方会浪费你一天”。读完之后，你会在画第一版原理图和写第一行 XDC 的时候就避开大部分坑。

**第二步：把 `02_templates/` 的三个文件改成自己的。**
`build.bat` 只需改 `VIVADO=` 的路径；`build.tcl` 改三个变量（工程名、顶层名、器件型号）；
`pins_key4.xdc` 换成自己板子的引脚，但保留注释里的判据说明。

**第三步：在第一次实现之后跑 `03_checks/`。**
先用 `--init` 把当前结果存成基线，之后每次改代码跑一次，
任何时序或资源回退都会立刻被指出来，不用每次人工翻报告。

---

## 已验证效果

以下结论都来自本项目实测，不是推测：

- `build.bat <project>` 在本机（Vivado 2017.4 + XC7Z010）连续调用 7 个工程、约 30 次构建，无一次因脚本本身失败；
  单工程从综合到比特流约 4 分钟。
- `03_checks/check_impl.py` 在本项目最后一次实现上运行，正确读出
  WNS = +3.089 ns、LUT 1003/17600(5.70%)、FF 677/35200(1.92%)、BRAM 1/60(1.67%)、
  DSP 6/80(7.50%)、IOB 11/100(11.00%)，并与基线比对通过。
- `03_checks/check_repro.py` 在本工程上运行，正确识别出 11 个源文件齐备、
  构建脚本与约束文件存在、比特流比全部源文件新（即“当前 bit 就是当前代码”）。
- `04_pitfalls/` 的 12 条**全部来自本项目实践**，其中 8 条保留了当时的原始读数或
  工具报错原文（`WNS−1.877 ns`、`K=1110`、`Please use ASCII characters`、
  `module 'key_debounce' not found` 等），可以直接对照排查。
  它们合计在本项目上消耗了约 3 个工作日的返工。
