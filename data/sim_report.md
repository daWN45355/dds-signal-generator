# 仿真验证结果

对应竞赛通知 3.3.5.1「仿真或验证结果，说明功能正确性是如何确认的」。

---

## 1 验证思路

本设计的正确性分两层确认，两层互相补位：

| 层次 | 手段 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 逻辑正确性 | Vivado xsim 行为级仿真 | 指令解析、参数更新、按键事件分发、非法输入处理的**逻辑**是对的 | 时序、电气、DAC 真实响应 |
| 物理正确性 | 上板 + 示波器 + 串口回传 | 波形真的出来了、频率相位幅度真的对、按键真的能用 | 边界条件下的内部状态 |

为什么只对 `cmd_parser` 做仿真，而不做整链路仿真？

这是一个有意的取舍。整链路的瓶颈不在逻辑而在**模拟侧**：DAC 的建立时间、重构滤波器、
探头负载，这些在行为级仿真里全是理想模型，仿得再"对"也不能说明板上的波形对。
相比之下，`cmd_parser` 是纯数字逻辑、有大量边界条件（非法字符、缺参数、超范围、
指令与按键交叉），正是最容易出隐性错误、也最适合仿真的部分。
其余模块（DDS 相位累加、波形合成、SPI 帧）的正确性由"示波器看到的波形"直接判定 ——
如果频率字算错，1 kHz 就会显示成别的数字，这种错误藏不住。

因此把仿真预算集中投入在 `cmd_parser`，用 13 个用例把它的状态空间打出边界，
其余模块靠上板观测。这是本次的验证策略，写在报告 5.8 节。

## 2 环境与运行方式

| 项目 | 内容 |
|---|---|
| 仿真器 | Vivado Simulator 2017.4（xsim），时间精度 1 ps |
| 流程 | `xvlog` → `xelab` → `xsim -runall`（三行批处理，无 GUI） |
| 顶层 | `tb_cmd` |
| 被测模块 | `cmd_parser.v`（行为级，非门级） |
| 脚本 | `sim/run_sim.bat`（双击即可，自动清理上次的 `xsim.dir`） |
| 运行时长 | 约 6 秒（编译 3 s + 仿真 3 s） |
| 仿真结束时刻 | 3970 ns（测试平台主动 `$finish`） |

`run_sim.bat` 的关键三行：

```bat
call "%V%\xvlog.bat" -work work ..\src\cmd_parser.v tb_cmd.v
call "%V%\xelab.bat" -debug typical -s tbsim tb_cmd
call "%V%\xsim.bat" tbsim -runall
```

注意 2017.4 的 `xvlog` **不支持** `-timescale` 命令行选项，
时间单位必须写在源码里（`` `timescale 1ns / 1ps ``），否则会报 unknown option。

## 3 用例与结果

测试平台的 `check` 任务做三件事：等参数稳定、比对 4 个参数寄存器
（频率 F、相位 P、波形 W、自动轮换 auto）、比对方向标志的置位与取值。
任一不符即打印 `[FAIL]` 并累加错误计数。

| # | 用例 | 激励 | 检查点（期望） | 实测 | 结论 |
|---|---|---|---|---|---|
| 1 | 复位默认值 | 释放复位 | F=1000 P=90 W=0 auto=0 D=+ | 一致 | 通过 |
| 2 | 方向指令 | 发 `D1\r` | 方向变为"减" | 一致 | 通过 |
| 3 | 频率指令 | 发 `F5000\r` | F 由 1000 变 5000 | 一致 | 通过 |
| 4 | 缺参数 | 发 `P\r`（只有字母无数字） | 指令被丢弃，参数不变 | 一致 | 通过 |
| 5 | 乱码注入 | 连续发非 ASCII / 非指令字节 | 所有参数保持不变 | 一致 | 通过 |
| 6 | 自动轮换 | 发 `W4\r` | `auto_wave` 置 1 | 一致 | 通过 |
| 7 | 按键改波形 | 触发一次按键波形事件 | W 由 0 变 1，且 `auto_wave` 被清零 | 一致 | 通过 |
| 8 | 按键频率加 | 触发一次按键频率事件 | F 由 5000 变 5100（步进 100） | 一致 | 通过 |
| 9 | 按键频率减 | 再触发一次（方向已是"减"） | F 由 5100 回 5000 | 一致 | 通过 |
| 10 | 按键相位加 | 触发一次按键相位事件 | P 由 90 变 105（步进 15°） | 一致 | 通过 |
| 11 | 方向回切 | 发 `D0\r` | 方向变回"加" | 一致 | 通过 |
| 12 | 连续回传 | 发 `S1\r` | `stream_en` 置 1 | 一致 | 通过 |
| 13 | 状态查询 | 发 `?\r` | 触发一次状态组帧发送 | 一致 | 通过 |

**13 / 13 通过，0 失败。** 末行输出 `ALL TESTS PASSED`。

### 3.1 三个用例为什么值得单独设计

- **用例 4（缺参数）**：`P\r` 是键盘手误的典型形态。若解析器把"没有数字"当成 0，
  相位会被静默设成 0°，用户会以为"相位功能坏了"。期望行为是**拒绝并保持原值**。
- **用例 5（乱码）**：串口上电瞬间、拔插 USB、上位机误发二进制都可能产生乱码。
  若解析器在非法字节上把状态机卡死，后续所有指令都失效，只能重新上电。
- **用例 7（按键 vs 指令冲突）**：`W4` 开了自动轮换，此时按波形键应该"接管"
  并退出轮换，否则用户按键后波形还在自己跳。这条交叉逻辑最容易漏。

## 5 仿真未覆盖的部分（如实说明）

仿真只覆盖 `cmd_parser` 一个模块，以下内容**没有**做仿真验证，其正确性由上板观测确认：

| 未仿真项 | 原因 | 上板如何确认 |
|---|---|---|
| DDS 相位累加与频率字换算 | 数学确定，无分支逻辑 | 示波器测周期，1 kHz 应读 1.000 ms |
| 波形合成（正弦/方波/三角/锯齿） | 查表与取位，易目视判断 | 四种波形逐个看形状 |
| TLV5618A SPI 时序 | 需器件模型；时序靠手册逐项核对 | DAC 有输出即说明帧序正确；无输出说明 CS/SCLK 错 |
| 双帧同步更新的相位时差 | 亚微秒级，仿真看不出"零时差"的意义 | 双迹观察 20 kHz 下相位是否长期稳定 |
| 按键消抖（20 ms）与连发（50 ms） | 时间尺度为毫秒，仿真代价大 | 按住键看回传报文是否每 50 ms 变一次 |
| 串口收发（115200） | 已由第 4/12/13 号用例间接覆盖字节流 | 实际终端能收到正确报文 |
| 门级/时序仿真（post-implementation） | WNS +3.089 ns 已零违例，静态时序分析覆盖了时序正确性 | 不需要 |

**关于门级仿真**：本设计没有做 post-synthesis / post-implementation 仿真。
理由是静态时序分析（STA）已经在 Slow/Fast 双角下检查了 1643 个端点，
建立、保持、脉宽三类全部零违例（见 `report/`），
门级仿真能额外发现的问题主要是 X 态传播与复位行为 ——
而这两点通过"所有寄存器显式赋初值 + 纯同步复位"在编码阶段就规避了。
这是一个有依据的取舍，不是省略。

## 6 如何自己复跑

```
双击 01_src\sim\run_sim.bat
```

脚本会先删掉上次的 `xsim.dir` 与日志，然后重新编译、精化、运行。
若编译失败，说明 `..\src\cmd_parser.v` 路径不对（工程包被移动过），
或 Vivado 路径与 `run_sim.bat` 里的 `set "V=D:\vivad\Vivado\2017.4\bin"` 不一致 —— 改这一行即可。

成功判据：末行出现 `ALL TESTS PASSED`，且 `[FAIL]` 计数为 0。
