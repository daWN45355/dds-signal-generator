# 案例模板

四个可以被直接套用的文件。**改三个变量就能跑**，不需要在 Vivado 图形界面里点。

| 文件 | 用途 | 复用方式 |
|---|---|---|
| `build.bat` | Windows 一键构建入口 | 只改 `VIVADO=` 的安装路径 |
| `build.tcl` | Vivado 批处理：建工程 → 综合 → 实现 → 生成 bit → 打印 WNS | 改顶部三个变量 |
| `pins_key4.xdc` | 时钟 + 4 按键 + 串行 DAC + UART 的约束模板 | 换引脚；**保留注释里的判据** |
| `report_outline.md` | 设计报告章节骨架 + 排版规格 | 按章节填内容 |

## 怎么搭一个最小工程

```
my_proj/
├── build.tcl            ← 从本目录复制
├── pins.xdc             ← 从 pins_key4.xdc 改
└── src/
    ├── my_top.v
    └── ...
```

然后在上一级目录放 `build.bat`，执行：

```
build.bat my_proj
```

约 4 分钟后得到 `my_proj/proj/my_proj.runs/impl_1/my_top.bit`，并在控制台打印 WNS。

## 这个骨架的设计取舍

- **每次构建都删掉 `proj/` 重建**。好处是构建结果与机器状态无关，天然可复现；
  代价是每次都要重新综合（约 4 分钟）。小工程值得，大工程应改成增量。
- **不做版本管理**。`.bit`、`proj/` 都不入仓，只保留 `src/`、`pins.xdc`、`build.tcl`。
  这样别人 clone 下来一条命令就能重建，也避免了“位流与源码不对应”的经典事故。
- **构建完立刻打印 WNS**。让时序状态在前台可见，而不是等人想起来了才去翻报告。

## 已验证

本项目 7 个分阶段工程（`phase2_dac` ~ `phase7_keyctl`）全部用这套骨架构建，
累计约 30 次，无一次因脚本本身失败。最后一次构建 WNS = +3.089 ns。

## 失效条件

- 工程含 Block Design / IP 核 / MIG：`build.tcl` 的建工程流程不够，见文件内注释。
- 源文件是 `.sv` 而非 `.v`：改 `glob` 的扩展名。
- 多时钟域：需要补充跨时钟约束，本模板只覆盖单时钟。
